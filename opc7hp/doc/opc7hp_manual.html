OPC7HP: the Harvard, pipelined OPC7

Chapter 1 summarises the machine for programmers. Chapter 2 gives each instruction its own page, after the instruction reference in Rodnay Zaks's Programming the Z80.

  • Sixteen 32-bit registers. Most instructions name a destination register, which is also their first operand, and a source register.
  • r0 always reads as zero. Writing it is allowed and changes nothing, but the flags are still set from the result, so an operation with destination r0 serves as a test.
  • r15 is the program counter. Read as a source, it gives the address of the next instruction. Writing it is a jump, and a jump leaves the flags unchanged.
  • Addresses and the program counter are 20 bits, so the machine addresses 1M 32-bit words. Reading r15 gives zeros in the top 12 bits. Memory is word addressed: there are no byte loads or stores.
  • By software convention, the BCPL code generator uses r13 as the link register and r14 as the stack pointer.

  • Z: the result is zero. S: bit 31 of the result is set. C: the carry out of an add, subtract or compare, or the bit shifted out by a shift or rotate. V: signed overflow from an add, subtract or compare.
  • EI enables hardware interrupts. Writing a non-zero SWI value with putpsr raises a software interrupt.
  • Only the instructions themselves set flags. The address and operand calculation (section 1.4) never does.
  • The PSR is read with getpsr and written with putpsr. getpsr puts V in bit 31 of its result, which also sets S, so getpsr followed by mi. or pl. tests overflow.

Both immediates are sign extended to 32 bits. A 16-bit immediate covers 0x0000 to 0x7FFF and 0xFFFF8000 to 0xFFFFFFFF. The exception is in and out, whose 16-bit I/O address space accepts any 16-bit constant. Load a full 32-bit constant with mov and then movt.

1.4Operand and address calculation

Every instruction first forms an effective address or data value, EAD. For the standard format, EAD = src + imm16. For the long format, EAD = imm20. The instruction then uses EAD as its operand, as a memory or I/O address, or as a jump target. Choosing r0 and a zero immediate gives these modes:

1.5Predicates

Every instruction carries a predicate in bits 31 to 29, written as a prefix to its mnemonic. If the predicate fails, the instruction does nothing at all and changes no flags.

  • Writing r15 with any instruction except the compares is a jump: mov pc, add pc, ld pc and so on. A jump leaves all the flags unchanged. A compare with destination r15 just compares.
  • Flags not listed for an instruction keep their values. In particular, C and V change only where shown.
  • add rd, rd shifts left one place, with C taking the bit shifted out.
  • bperm builds each byte of the result from a 4-bit field of the selector, with byte 3 on the left. Bits 1 and 0 of a field pick a byte of rs, and bit 2 makes the byte zero. For example, 0x3210 leaves rs unchanged, 0x0123 reverses its bytes and 0x4441 moves byte 1 to byte 0 and clears the rest.
  • Unused opcodes are 0x0F, 0x14, 0x15 and 0x17.

1.7Reset and interrupts

  • Reset starts execution at address 0 with interrupts disabled.
  • Hardware interrupts come from int_b[1:0], active low, while EI is set. An interrupt is taken as an instruction completes, and enters the handler at address 0x0004 for int_b[1] or 0x0002 for int_b[0]. If both are low, int_b[1] wins. A software interrupt, from putpsr writing a non-zero SWI, also uses 0x0002, so the handler reads the PSR to tell them apart.
  • Taking an interrupt saves the return address and the flags, then clears EI. rti pc, pc returns and restores them, with SWI cleared.
  • On opc7hpcpu, interrupts are precise. Everything before the interrupted point has completed, nothing after it has had any effect, and a store, in or out already sent to memory is never repeated.

Each port carries one access at a time. A request is taken at the end of a cycle in which its wait is low. The reply comes in the first later cycle with the wait low, and a write is complete as soon as it is taken. Tie both waits low for single-cycle memory such as block RAM. The waits must not depend on the CPU's outputs in the same cycle.

1.9Timing

The original opc7cpu runs one instruction at a time through its fetch (FET), address (EAD), memory (RDM/WRM) and execute (EXEC) states. opc7hpcpu overlaps four pipeline stages: FD (fetch), EA (address), MEM (memory) and EX (execute). It starts one instruction per cycle, apart from the costs below, and averages about 1.33 cycles per instruction on the BCPL test programs.

1.10Changes from the original OPC7 specification

  • scmp (0x16) added for signed comparisons. The original table showed it as cmp.
  • Predicate 001, written 0., means never execute in all the CPUs, both emulators and the assembler. The original opc7cpu executed it.
  • getpsr used to clear C in the copy it read. It now reads the PSR as it is.
  • in sets S and Z from the value read, and out leaves the flags alone, the same as loads and stores.
  • asr shifts in bit 31; the original table said bit 15. Shifts and rotates set C, and stores, out, writes to r15 and rti leave Z alone, which the original flag notes didn't say.
  • The long forms are written ljsr, lmov, lsto and lld.
  • An interrupt saves V along with the other flags, and rti restores it, as the emulators always did. The RTL used to clear V on rti.
  • opc7hpcpu adds the Harvard ports, the iwait and dwait inputs and the hlt output. Interrupts are precise.

Description

The source plus the immediate is subtracted from the destination register, as sub does, but only the flags keep the result.
